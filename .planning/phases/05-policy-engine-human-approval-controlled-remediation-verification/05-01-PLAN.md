<task type="auto">
  <name>Task 2: PolicyEngine with approval prerequisites and destructive action guards</name>
  <files>apps/policy/engine.py, tests/unit/test_policy_engine.py</files>
  <action>
    Implement `PolicyEngine` in `apps/policy/engine.py`:
    - Evaluates action requests:
      1. Determines `RiskTier` via `RiskClassifier`.
      2. If `DESTRUCTIVE`: returns `decision=REJECTED`, `requires_approval=False`, reason="Operation is permanently prohibited by safety policy."
      3. If `READ` or `LOW`: returns `decision=ALLOWED`, `requires_approval=False`.
      4. If `MEDIUM`: allowed with audit warning unless configured for strict approval.
      5. If `HIGH`:
         - Checks `proposal_id`: if missing -> `decision=BLOCKED`, `requires_approval=True`.
         - Queries `storage.get_action_proposals(incident_id)`:
           - If status != `approved` or `approved_by` is missing -> `decision=BLOCKED`, `requires_approval=True`, reason="Action requires verified human approval before execution."
           - If status == `approved` with valid operator -> `decision=ALLOWED`, `requires_approval=False`, reason=f"Action approved by operator '{approved_by}'."
    - Method `validate_execution_allowed(proposal_id: str) -> bool`: helper invoked by mutating MCP tools before touching target services.
    Write `tests/unit/test_policy_engine.py` testing evaluation of READ queries, blocking unapproved rollback proposals, approving validated proposals, and rejecting destructive actions.
  </action>
  <verify>
    <automated>.venv\Scripts\python -m pytest tests/unit/test_policy_engine.py -v</automated>
    <fails_when>non-zero exit code or policy engine allows unapproved HIGH-risk execution</fails_when>
  </verify>
  <done>
    `PolicyEngine` strictly enforces approval requirements for HIGH-risk actions and blocks unauthorized execution attempts.
  </done>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Agent / Caller → PolicyEngine | Proposal execution requests for production changes |
| Human Operator → ApprovalManager | Approval/Rejection decisions modifying action lifecycle state |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-01 | Elevation of Privilege | Autonomous Action Bypass | critical | mitigate | `DeploymentMCP` validates proposal state directly through `PolicyEngine.validate_execution_allowed()`; execution is impossible without database-persisted approval. |
| T-05-02 | Tampering | Destructive Operation Injection | critical | mitigate | `RiskClassifier` identifies destructive keywords and permanently rejects them with `POLICY_VIOLATION`. |
| T-05-03 | Repudiation | Unattributed Approvals | high | mitigate | `ApprovalManager` mandates non-empty `operator_id` string and logs every approval with timestamp in `GovernanceAuditLogger`. |
</threat_model>
