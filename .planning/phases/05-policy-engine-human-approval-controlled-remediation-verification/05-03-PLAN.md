  <action>
    Implement `RemediationVerifier` in `apps/verification/verifier.py`:
    - Class `RemediationVerifier`:
      - Accepts metric collector callbacks / provider functions (e.g., query error rate, query connection pool).
      - `verify_remediation(target: VerificationTarget, proposal_id: str, incident_id: str) -> VerificationResult`:
        - Runs async polling loop until:
          a) Conditions are met for `min_consecutive_successes` passes -> returns `VerificationResult(status='verified')`.
          b) Elapsed time exceeds `timeout_sec` -> returns `VerificationResult(status='failed', summary='Verification timed out before metrics stabilized')`.
        - Default verification rule for `payment-service` rollback:
          - Condition 1: `error_rate < 0.01` (< 1.0%).
          - Condition 2: `active_connections < 15` (nominal connection pool).
        - Records each `MetricSample` in history.
    Extend `tests/unit/test_remediation_verifier.py`:
    - Test immediate recovery (metrics pass on first cycles).
    - Test delayed recovery (metrics fail first 2 cycles, pass subsequent cycles).
    - Test timeout failure (service remains broken, error rate persists high).
    - Test custom condition sets and fast poll interval for testing (<0.1s).

<task type="auto">
  <name>Task 3: Incident closure pipeline, audit logging, and n8n notification dispatch</name>
  <files>apps/verification/closure.py, tests/unit/test_incident_closure_pipeline.py, tests/integration/test_remediation_verification_live.py</files>
  <action>
    Implement `IncidentClosurePipeline` in `apps/verification/closure.py`:
    - Connects `RemediationVerifier`, `InvestigationStorage`, `GovernanceAuditLogger`, and `N8nTools`:
      - `execute_verification_and_close(incident_id: str, proposal_id: str, root_cause: str, winning_hypothesis_id: Optional[str] = None, target: Optional[VerificationTarget] = None) -> ClosureResult`:
        1. Runs `RemediationVerifier.verify_remediation(...)`.
        2. If verified:
           - Updates proposal status in `InvestigationStorage` to `verified`.
           - Calls `storage.close_incident(incident_id, root_cause=root_cause, winning_hypothesis_id=winning_hypothesis_id, summary="Remediation verified by telemetry loop.")`.
           - Emits `incidents.updated` Kafka event with status `resolved`.
           - Calls `N8nTools.execute_workflow("incident-resolution-alert", payload={...})` to broadcast Slack/Jira notification.
           - Records audit entry in `GovernanceAuditLogger` with outcome `INCIDENT_CLOSED_VERIFIED`.
        3. If failed:
           - Updates proposal status in `InvestigationStorage` to `failed`.
           - Updates incident summary with failure details and status `escalated`.
           - Dispatches escalation notification via `N8nTools`.
           - Records audit entry with outcome `REMEDIATION_VERIFICATION_FAILED`.
    Write `tests/unit/test_incident_closure_pipeline.py`:
    - Test complete end-to-end happy path: proposal executed -> verified -> incident closed -> audit entry written -> n8n notified.
    - Test failed verification path: proposal failed -> incident escalated -> alert sent -> audit logged.
    Create `tests/integration/test_remediation_verification_live.py` marked `@pytest.mark.integration` for live container scenarios.
  </action>
