<objective>
Implement the telemetry ingestion pipeline and deterministic anomaly detection engine. Stream Kafka logs, metrics, and deployment events into PostgreSQL (`aegisops_db`), continuously evaluate sliding-window deterministic rules (error spikes, latency anomalies, DB connection pool timeouts), and automatically generate deduplicated incidents on `incidents.created`.

Purpose: Provide a reliable, non-blocking telemetry bridge between operational streams and durable storage, detecting real failures deterministically within seconds without expensive or hallucination-prone LLM polling.
Output: PostgreSQL telemetry DDL (`schema.sql`), ingestion consumer service (`apps/ingestion/`), anomaly detection engine (`apps/detection/`), and unit tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Kafka Topics → Consumer | Untrusted telemetry stream containing arbitrary log messages and metric values |
| Consumer → PostgreSQL | Database connection inserting telemetry rows |
| Detector → Kafka Producer | Automated publishing of `incidents.created` events |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-04 | Tampering | SQL Injection in Log Ingestion | high | mitigate | All SQL queries and batch inserts use parameterized statements via asyncpg; zero raw string interpolation. |
| T-02-05 | Denial of Service | Kafka Telemetry Flooding | medium | mitigate | Micro-batching caps memory buffer size, dropping/alerting on memory limits rather than crashing the process. |
| T-02-06 | Denial of Service | Alert Storming / Duplicate Incidents | high | mitigate | Sliding-window deduplication and configurable cooldown (10m) prevent runaway incident creation. |
| T-02-SC | Repudiation | Incident Provenance | low | mitigate | Each created incident includes triggering evidence, rule ID, and timestamps in its metadata payload. |
</threat_model>
