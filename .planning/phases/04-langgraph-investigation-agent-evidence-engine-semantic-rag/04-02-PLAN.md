  <files>apps/agent/reasoning/__init__.py, apps/agent/reasoning/hypotheses.py, tests/unit/test_hypothesis_scoring.py</files>
  <action>
    Implement multi-hypothesis evaluation and calibrated scoring in `apps/agent/reasoning/hypotheses.py`:
    - `HypothesisEngine` class:
      1. Generates 3–4 standard competing hypotheses for operational incidents:
         - H1: Database connection pool exhaustion caused by recent code release (e.g. v2.8.1 leak).
         - H2: Infrastructure degradation or external database server resource bottleneck.
         - H3: Unexpected high traffic surge / transactional load spike.
         - H4: Downstream payment gateway / third-party dependency outage.
      2. Clear classification categories:
         - `Facts`: validated observations from `CanonicalEvidence`.
         - `Hypotheses`: candidate explanations with quantified confidence.
         - `Assumptions`: unverified baseline assumptions.
         - `Alternative Explanations`: secondary possibilities.
      3. Calibrated Bayesian Likelihood Scoring:
         - Computes posterior probabilities based on supporting and refuting evidence weights.
         - Normalizes confidence distribution so competing active hypotheses sum to 1.0 (100%).
         - Overconfidence guardrails:
           - Capped at 70% if evidence originates from only one source tool.
           - Requires corroboration across >= 2 independent tools (e.g. Database MCP + GitHub MCP) to achieve > 85% confidence score.
           - Refuting evidence significantly penalizes hypothesis score and transitions status to `refuted`.
      4. Persistence integration:
         - Syncs hypothesis updates with `InvestigationStorage` / `Incident MCP` schema (`incident_hypotheses`).
    Write `tests/unit/test_hypothesis_scoring.py` testing hypothesis initialization, evidence attachment, refuting evidence penalty, Bayesian normalization, multi-source corroboration cap, and storage sync.
