  <files>apps/mcp_incident/storage.py, apps/api/dependencies.py, apps/api/routers/incidents.py, apps/api/routers/observability.py, apps/api/main.py, tests/unit/test_api_incidents.py, tests/unit/test_api_observability.py, tests/integration/test_dashboard_api_live.py</files>
  <action>
    Implement backend REST endpoints and security dependencies in `apps/api/`:
    1. In `apps/mcp_incident/storage.py`:
       - Add `list_incidents(status: Optional[str] = None, severity: Optional[str] = None, limit: int = 50) -> List[IncidentDetail]`.
       - Support both in-memory store and live asyncpg connection pool.
    2. Create `apps/api/dependencies.py`:
       - Implement `require_operator_authorization(x_operator_id: Optional[str] = Header(None), x_operator_role: Optional[str] = Header("sre"))`:
         - Checks non-empty `X-Operator-Id`; raises HTTP 401 if missing or whitespace.
         - Validates role against authorized set (`sre`, `admin`, `oncall`); raises HTTP 403 if unauthorized.
         - Returns `OperatorContext(operator_id=..., role=...)`.
    3. Create `apps/api/routers/incidents.py`:
       - Mount router with prefix `/api/incidents`.
       - `GET /`: returns incident list with optional query params `status`, `severity`, `limit`.
       - `GET /{incident_id}`: returns single incident detail or 404.
    4. Create `apps/api/routers/observability.py`:
       - Mount router with prefix `/api/observability`.
       - `GET /status`: performs active TCP/HTTP socket probes against infrastructure (PostgreSQL `:5432`, Kafka `:9092`, Qdrant `:6333`, n8n `:5678`) and MCP servers (`Logs :8002`, `DB :8003`, `GitHub :8004`, `Incident :8005`, `Deployment :8006`, `n8n :8007`, `payment-service :8001`).
       - Categorizes each service into one of 4 explicit states:
         - `healthy`: probe succeeded (HTTP 200 or TCP connected) and last telemetry timestamp is < 60s ago.
         - `unhealthy`: probe explicitly failed (HTTP 5xx, connection refused).
         - `unknown`: probe timed out (timeout > 1.5s) or host is unresolvable.
         - `stale`: service was reachable, but last telemetry sample or heartbeat is > 60s old.
       - Returns `ObservabilityStatus` with sanitized details, latency in ms, and overall system status.
    5. Register routers in `apps/api/main.py`.
    Write `tests/unit/test_api_incidents.py` and `tests/unit/test_api_observability.py` testing endpoints offline with mocked probes and storage.
    Create `tests/integration/test_dashboard_api_live.py` marked `@pytest.mark.integration` testing live probe execution against active listeners.
  </action>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → Core API | Public HTTP REST requests to `/api` passing `X-Operator-Id` |
| Core API → Storage | Database read queries for incident list |
| Core API → Services | Active TCP/HTTP probe socket connections with strict timeouts |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-01 | Information Disclosure | Observability Endpoints | medium | mitigate | Observability router only returns connection status, ports, and latency; credentials, passwords, and connection strings are redacted. |
| T-06-02 | Denial of Service | Unbounded Incident Listing | medium | mitigate | `list_incidents` enforces a maximum pagination limit of 100 items. |
| T-06-03 | Denial of Service | Active Probing Hang | medium | mitigate | Observability probes enforce 1.5s socket timeout per target to prevent hung requests. |
</threat_model>
