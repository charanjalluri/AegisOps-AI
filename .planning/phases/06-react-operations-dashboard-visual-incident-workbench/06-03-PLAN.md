  <name>Tracer: Backend governance REST router with server-side auth, parameter binding, TTL expiration, and replay prevention</name>
  <files>apps/api/routers/governance.py, apps/api/main.py, tests/unit/test_api_governance.py, tests/integration/test_dashboard_api_live.py</files>
  <action>
    Implement governance REST router in `apps/api/routers/governance.py`:
    1. Import `require_operator_authorization` dependency from `apps/api/dependencies.py`.
    2. `GET /api/incidents/{incident_id}/proposals`: retrieves proposals from `InvestigationStorage`.
    3. `POST /api/proposals/{proposal_id}/approve`:
       - Enforces `Depends(require_operator_authorization)`.
       - Accepts optional comment body `{"comment": Optional[str]}`. Uses authenticated `operator_ctx.operator_id`.
       - Calls `ApprovalManager.approve_proposal()`. Records approval timestamp for TTL checking.
    4. `POST /api/proposals/{proposal_id}/reject`:
       - Enforces `Depends(require_operator_authorization)`.
       - Accepts mandatory reason `{"reason": str}`. Uses authenticated `operator_ctx.operator_id`.
       - Calls `ApprovalManager.reject_proposal()`.
    5. `POST /api/proposals/{proposal_id}/execute`:
       - Enforces `Depends(require_operator_authorization)`.
       - Accepts optional execution parameters body `{"service": str, "target_version": str}`.
       - Parameter binding check: verifies parameters match approved proposal. If mismatched, returns HTTP 400.
       - Replay prevention check: verifies proposal status is `approved`. If `executed` or `verified`, returns HTTP 409 Conflict.
       - Expiration check: verifies `approval_timestamp` is within TTL window (default 1800s / 30m). If expired, transitions proposal to `expired` and returns HTTP 409 Conflict.
       - Invokes `DeploymentTools.rollback_deployment()`, strictly evaluating `PolicyEngine.validate_execution_allowed()`.
    6. `GET /api/incidents/{incident_id}/verification-status`:
       - Returns current verification status (`status`: `idle` | `in_progress` | `verified` | `failed`, `samples`: List[MetricSample], `consecutive_passes`: int, `target_passes`: int, `conditions`: List[MetricCondition]).
    7. `POST /api/incidents/{incident_id}/verify-and-close`:
       - Enforces `Depends(require_operator_authorization)`.
       - Triggers `IncidentClosurePipeline.execute_verification_and_close()`.
    8. `GET /api/audit`:
       - Enforces `Depends(require_operator_authorization)`.
       - Retrieves immutable entries from `GovernanceAuditLogger`.
    Register router in `apps/api/main.py`.
    Write `tests/unit/test_api_governance.py` testing auth enforcement, parameter mismatch rejection, replay prevention, expiration handling, and verification triggers offline.
    Extend `tests/integration/test_dashboard_api_live.py` marked `@pytest.mark.integration` testing the complete end-to-end lifecycle with running API and mock MCP endpoints.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Operator Browser → Core API | Submitting approval decisions and executing rollbacks |
| Core API → Policy Engine | Pre-execution safety and policy validation gate |
| Core API → Storage | Updating proposal states and logging immutable audit records |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-06 | Elevation of Privilege | Bypassing Operator Authorization | critical | mitigate | `require_operator_authorization` dependency validates `X-Operator-Id` and `X-Operator-Role` server-side before any approval, rejection, or execution. |
| T-06-07 | Tampering | Proposal Parameter Tampering | high | mitigate | `execute` endpoint verifies caller parameters strictly match the approved proposal snapshot in storage; deviations return HTTP 400. |
| T-06-08 | Replay / Elevation | Proposal Replay & Stale Execution | high | mitigate | Proposals enforce single-use state transition (`executed`), and approvals expire after 30m TTL. Re-execution of executed or expired proposals returns HTTP 409. |
| T-06-09 | Repudiation | Unrecorded Approval Actions | high | mitigate | Every approve, reject, rollback, and closure action writes an immutable record to `GovernanceAuditLogger`. |
</threat_model>
