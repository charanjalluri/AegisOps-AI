# Plan 07-02: Multi-Scenario Benchmark Library & AI Evaluation Runner

## 1. Objective
Deliver a comprehensive benchmark library containing 5 diverse operational incident scenarios and an automated quantitative evaluation suite (`make evaluate`) measuring RCA accuracy, tool selection precision & recall, hallucination rate, remediation proposal validity, and verification reliability.

---

## 2. Context & Requirements
- **DEMO-03**: Additional ground-truth scenario library (`bad-deployment`, `memory-leak`, `slow-query`, `service-dependency-failure`).
- **DEMO-04**: AI evaluation benchmarking suite (`make evaluate`) measuring RCA accuracy, tool selection precision, hallucination rate, and verification reliability.
- **Budget & Guardrail Compliance**: Investigation budget strictly enforces max 20 tool calls, max 5 expensive operations, and 300s timeout per scenario.

---

## 3. Tasks

### Task 1: Multi-Scenario Benchmark Library (`demo/scenarios/*.yaml`)
- Create 4 additional declarative operational failure scenarios:
  1. `demo/scenarios/bad-deployment.yaml`:
     - Fatal startup crash / missing environment variable triggering crash loop backoff and connection refused errors.
     - Ground truth: bad deployment configuration, expected rollback or config fix.
  2. `demo/scenarios/memory-leak.yaml`:
     - Unbounded heap accumulation in payment session cache causing JVM/Node GC pauses > 2,000ms and OOM restart.
     - Ground truth: memory leak in session cache, expected pod restart or rollback.
  3. `demo/scenarios/slow-query.yaml`:
     - Unindexed sequential scan on `payment_transactions` under peak load, lock contention, p95 latency > 2,500ms.
     - Ground truth: unindexed slow query / database query performance degradation.
  4. `demo/scenarios/service-dependency-failure.yaml`:
     - Upstream banking fraud verification gateway latency spike and 504 Gateway Timeouts triggering payment failures.
     - Ground truth: third-party dependency outage / upstream timeout, expected circuit-breaker fallback.

### Task 2: Quantitative Evaluation Metrics (`apps/evaluation/metrics.py`)
- Implement evaluation metric calculators:
  - `evaluate_rca_accuracy(rca_report, ground_truth) -> BenchmarkScore`: Keyword recall and category classification accuracy.
  - `evaluate_tool_selection(tool_history, ground_truth) -> BenchmarkScore`: Precision, recall, F1-score, and penalties for forbidden or runaway tool calls.
  - `evaluate_groundedness(rca_report, tool_history) -> BenchmarkScore`: Proves all cited facts match actual tool payload provenance ($H = 0.0$).
  - `evaluate_action_proposal(proposal, ground_truth) -> BenchmarkScore`: Validates remediation action type, parameters, and risk level.
  - `evaluate_verification(verification_result, ground_truth) -> BenchmarkScore`: Validates metric verification against expected threshold conditions.
  - `compute_benchmark_summary(scenario, evaluation_result) -> ScenarioBenchmarkResult`.

### Task 3: AI Evaluation Suite Runner CLI (`apps/evaluation/runner.py`)
- Implement the benchmark evaluation CLI:
  - CLI flags: `--scenario <id>`, `--all`, `--json`, `--output <file>`.
  - Executes investigations across selected scenarios using the LangGraph state machine.
  - Computes per-scenario metrics and composite benchmark scores.
  - Renders a clean ASCII/Markdown summary table displaying:
    - Scenario ID
    - Primary Root Cause Detected
    - RCA Score (%)
    - Tool F1 Score (%)
    - Groundedness (%)
    - Action Match (Pass/Fail)
    - Overall Benchmark Score (%)
  - Returns exit code 0 if all scenario scores meet or exceed passing threshold (80.0%), non-zero on regression.

### Task 4: Unit & Benchmark Tests (`tests/unit/test_evaluation_metrics.py`, `tests/unit/test_scenario_benchmark.py`)
- Unit tests:
  - Verify metric calculations for edge cases (zero tool calls, perfect execution, missing keywords, ungrounded hallucinated facts).
  - Test benchmark execution of all 5 scenarios in offline mode, ensuring 100% test reproducibility within <5 seconds.
