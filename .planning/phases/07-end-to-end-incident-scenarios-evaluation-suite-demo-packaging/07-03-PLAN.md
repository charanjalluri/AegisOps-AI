# Plan 07-03: End-to-End Demo Scripts, Observability Dashboards & Quickstart Packaging

## 1. Objective
Package the entire AegisOps AI platform with single-command demo execution (`make demo`), clean state reset (`make reset-demo`), automated benchmark evaluation (`make evaluate`), pre-configured Prometheus/Grafana dashboards, and comprehensive quickstart documentation (`docs/QUICKSTART.md`).

---

## 2. Context & Requirements
- **DEMO-01**: Microservice simulator emits realistic operational telemetry and recovers after controlled rollback.
- **DEMO-02**: Reproducible demo execution (`make demo`) driving the full closed loop: failure injection $\rightarrow$ anomaly detection $\rightarrow$ LangGraph investigation $\rightarrow$ operator approval $\rightarrow$ rollback execution $\rightarrow$ post-remediation verification $\rightarrow$ verified incident closure.
- **DEMO-04**: Single-command evaluation benchmark (`make evaluate`) providing quantitative confidence scores.
- **Packaging Constraints**:
  - `make demo` and `make reset-demo` must run deterministically on developer workstations.
  - Zero plain credentials in LLM prompts or tool arguments.
  - Clean state isolation: reset scripts touch only demo databases and test incidents.

---

## 3. Tasks

### Task 1: End-to-End Demo Runner Script (`scripts/run_demo.py`)
- Implement `run_demo.py`:
  - Flags: `--standalone` (in-memory mode for fast offline testing), `--auto-approve` (bypasses terminal prompt for CI/automated runs), `--scenario <path>`.
  - Step 1: Check dependencies (Postgres, Kafka, Qdrant, Payment Service, or activate mock providers).
  - Step 2: Inject flagship failure (`database-connection-leak.yaml`).
  - Step 3: Emit / observe telemetry anomaly and create `INC-DEMO-001`.
  - Step 4: Execute autonomous LangGraph investigation; display live evidence, tool calls, and hypotheses.
  - Step 5: Synthesize RCA report (92% confidence, primary root cause: connection pool leak in v2.8.1).
  - Step 6: Present Human Approval Gate; capture operator approval (`sre-lead@aegisops.ai`, `senior_sre`).
  - Step 7: Execute policy-gated rollback to `v2.8.0`.
  - Step 8: Execute closed-loop verification loop polling telemetry until `error_rate < 0.01` and `active_connections < 15.0`.
  - Step 9: Close incident as `resolved` and record immutable audit entry.
  - Step 10: Print ASCII summary scorecard.

### Task 2: Comprehensive State Reset Script (`scripts/reset-demo.py`)
- Update `scripts/reset-demo.py`:
  - Truncates `payment_transactions` in `demo_payment_db`.
  - Deletes test incidents (`INC-DEMO-*`, `INC-BENCH-*`) and their associated proposals/evidence in `aegisops_db`.
  - Resets `payment-service` simulator version to `v2.8.0` and resets connection pool saturation.
  - Resets in-memory mock deployment states to nominal baseline.

### Task 3: Prometheus Alerting Rules & Grafana Dashboard Provisioning
- Create `infrastructure/prometheus/alert_rules.yml`:
  - Rules for `PaymentServiceHighErrorRate`, `PaymentServiceHighLatency`, and `PaymentServiceDBConnectionPoolExhausted`.
- Update `infrastructure/prometheus/prometheus.yml` to include rule files.
- Create `infrastructure/grafana/dashboards/aegisops_incident_dashboard.json`:
  - Panels: Error Rate (%), P95 Latency (ms), Connection Pool Utilization (%), Active Incidents Gauge, Investigation Timeline.
- Create Grafana provisioning descriptors in `infrastructure/grafana/provisioning/`.

### Task 4: Developer Makefile Updates
- Add targets to `Makefile`:
  - `demo`: runs `$(PYTHON) scripts/run_demo.py --auto-approve`
  - `evaluate`: runs `$(PYTHON) -m apps.evaluation.runner --all`
- Update `tests/unit/test_makefile_targets.py` to assert `demo:` and `evaluate:` targets exist.

### Task 5: Developer Quickstart Guide (`docs/QUICKSTART.md`)
- Author comprehensive, verified quickstart guide:
  - Prerequisites (Docker Desktop, Python 3.12, Node.js 20+).
  - Architecture diagram and service port mapping table.
  - Step-by-step walkthrough: `make setup`, `make up`, `make seed`, `make demo`, `make evaluate`, `make reset-demo`.
  - Web UI guide: accessing React Workbench on port `5173`, viewing triage queue, approving actions, and inspecting MCP tools.
  - Troubleshooting FAQ.

### Task 6: Unit & Integration Tests
- Unit tests (`tests/unit/test_demo_scripts.py`):
  - Test `run_demo.py` in standalone offline mode.
  - Test `reset-demo.py` idempotency.
- Integration test (`tests/integration/test_end_to_end_demo_live.py`):
  - Tests end-to-end demo execution flow with mock/live service integration.
